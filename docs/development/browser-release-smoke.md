# 首次使用浏览器验收

`web/e2e/public-release-smoke.spec.ts` 必须连接尚无用户的真实服务。测试先读取身份状态并确认 `setup_required=true`、用户数为零；不能用已有管理员或 Mock 响应代替。

测试通过页面创建首个管理员，确认真实 `201` 和用户身份，检查知识概览默认页、13 个页面的标题、路径与当前导航，从资料库“添加资料”进入上传与处理，再点击“上传资料”打开并用 Escape 关闭上传弹窗。窄屏检查原生导航抽屉与关闭状态，随后实际注销、确认会话失效，再使用同一账号登录并读回身份。全过程不上传原件、不提交模型查询，因此不验证模型答案或入库质量。

本机执行示例：先准备独立数据库、对象桶、Milvus collection 和 Redis 空间，再启动独立 loopback 服务，将 `EKB_E2E_BASE_URL` 指向它，运行 `cd web && npm run e2e`。共享已有基础设施的新应用状态，与全新 Docker 基础设施属于不同验收范围，报告必须分别注明。

CI 在独立 Compose 项目和新数据卷中执行完整首次使用流程，支持手动触发。各 job 设置运行上限；无论成功或失败，在销毁临时服务前保存 Compose 状态、各服务最后 400 行脱敏日志、Playwright JSON 报告、失败截图、错误上下文和失败 trace。诊断收集不输出 `.env`、容器环境或密码；浏览器 trace 仅针对该临时随机账号，不能指向真实业务账号。产物保留 7 天。

2026-10-04 的云端第二轮已真实完成默认 PostgreSQL/Milvus 部署和浏览器安装；smoke 因旧标题“初始化管理员账号”与当前“初始化 EvoKB 管理员”不一致而失败，原失败保留。标题修复使用当前唯一 `h1` 契约，未删除首次创建步骤或放宽匹配。后续本机和云端结果分别绑定实际源码与运行产物记录。

本机在共享真实基础设施中的独立应用空间复现了旧测试失败。首轮新测试还发现“添加资料”已改为先导航到上传与处理，补齐第二个“上传资料”点击后，第二份从零用户开始的完整流程通过，耗时 4.2 秒，未跳过页面或弹窗。独立数据库、MinIO、Milvus、Redis 的 16 项只读交叉检查通过：管理员和 BCrypt 哈希已保存、注销和再次登录均有审计记录，原件、入库批次、查询会话和索引行仍为零。两个本机失败环境及证据保留，独立应用随后正常停止。

这批前端通过 lint、类型检查、生产构建和依赖审计，漏洞数为零；本机没有构建第二套 Docker 基础设施，也没有请求模型。修订后的云端首次使用流程仍须在推送后独立执行，不能用本机成功代替云端结果。
