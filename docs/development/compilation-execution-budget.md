# 编译阶段与模型请求期限

每次数据库领取的编译尝试都有固定 `stage_deadline`。Summary、Concept、Graph、Wiki、条目关联和独立向量修复使用同一尝试的发布权限对象，在捕获完整输入后才允许模型请求。打开执行范围不会提前检查尚未捕获的输入。

`CompilationExecutionBudget` 保存该绝对期限、原发布权限和时钟。共享 Chat / Serving HTTP 边界用剩余时间限制请求和完整响应体等待；Spring Retry 的毫秒计时可以取最小 1 ms，但实际请求等待、退避和数据库期限仍使用原剩余预算，不续租、不增加六次尝试。异步请求返回检查显式捕获进入调用时的权限对象，不依赖线程池继承 ThreadLocal。范围退出恢复上层范围，普通无任务请求继续使用其配置期限。

模型成功返回 HTTP 后的非法 JSON / 输出类型约束，以及模型引文审计的非法结构，使用 `ModelOutputRejectedException` 交给既有后台五次有限重试。HTTP 鉴权、账户错误、源权限撤销、代码配置错误保留其原分类。来源或旧缓存不可用不能伪装成可重试模型提案。阶段到期异常即使被编译服务包装，也保存 `STAGE_DEADLINE_EXPIRED`；第 5 次失败进入隔离。

该机制覆盖模型和 Serving HTTP 请求观察。2026-11-02 又补齐编译作用域的 MinIO 完整响应体与 Milvus SDK gRPC 调用期限，见 [编译远端 I/O 期限](compilation-io-deadline.md)。这仍不表示 JDBC 连接获取/锁等待/网络读取、索引迭代器的结束清理、Raw/PDF 等全部 I/O 都有统一强制取消。数据库短事务和发布 fence 继续负责最终提交权限。

## 已保留的实际失败

2026-10-07，正常页面生成的任务 `605015db-5ce9-4f06-9d99-556518e794b0` 第 5 次尝试在 600 秒期限后仍进入独立 Luna 判断调用，最终自然失败，耗时约 844 秒。五条失败记录保留，原 14 条事实未被新编译覆盖，没有发布新 Summary；未直接核对的对象字节或孤儿对象不能据此声称不存在。完整失败模型响应未被原程序记录，标为 `NOT_CAPTURED`。

这项修复的独立模型诊断应保存真正返回的内容和解析结果，保留候选与证据身份。诊断不能替代旧任务缺失的响应，也不能把旧事实或重试耗尽后的第六次尝试当作业务闭环成功。源码候选的通过状态以独立验收报告为准。

## 可重跑的分层验证

- `test-grounding-focused-junit.py`：冻结候选和原响应适配器，保留旧实现违反类型/期限约定的反例；本地 HTTP 测试覆盖完整响应、权限撤销、非阶段超时、原次数和原请求正文。
- `test-postgres-compilation-budget.py`：独立保留 PostgreSQL schema，实际 `claim -> captureInputs -> request budget`，检查输入捕获顺序、事务释放和撤权，不改生产任务或伪造完成。
- `verify-backend.py`：完整清理构建、鲜 XML、源码清单与不可变 JAR 绑定，然后才允许正常部署。
- 任务页面：中文失败阶段、下次尝试时间和五次隔离信息；管理员可展开原诊断，执行中与历史失败分开显示。
